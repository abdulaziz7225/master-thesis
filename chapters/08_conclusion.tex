\chapter{Conclusion}
\label{chap:conclusion}

This thesis set out to answer whether \acs{Wasm}/SpinKube is a viable alternative to Docker for high-density \acs{HTTP} microservices in Kubernetes, comparing four variants across five metrics: \acs{OCI} artifact size, startup latency, runtime performance under load, memory footprint, and developer experience.

The primary 4-variant experiment (wasm-rust, wasm-tinygo, docker-rust, docker-golang) uses SpinKube/Wasmtime (\acs{WASI}~P2) as the \acs{Wasm} execution environment. Quantitative benchmark measurements are pending cluster execution (Section~\ref{sec:eval_performance}). The developer experience assessment is complete (Section~\ref{sec:eval_dx}) and reveals that the transition from \acs{WASI}~P1 (WasmEdge) to \acs{WASI}~P2 (SpinKube) dramatically reduces ecosystem friction: standard \texttt{net/http} works with TinyGo under \texttt{-target=wasip2}, the \texttt{spin-sdk} for Rust eliminates proprietary socket crates, and the SpinOperator replaces the need for custom \texttt{crun} compilation.

The historical \acs{WASI}~P1 results (Appendix~\ref{app:wasmedge_p1}) demonstrate that \acs{Wasm} variants offer compelling binary size and cold-start advantages but face severe throughput limitations under concurrent load when constrained by the single-threaded \acs{WASI}~P1 I/O model (24\,\acs{RPS} vs.\ 510\,\acs{RPS} for Docker at 50 concurrent virtual users). The central open question---whether SpinKube's request-handler model closes this gap---will be answered by the pending benchmark execution.

The memory-bandwidth benchmark (02-memory-bandwidth, implemented in \texttt{benchmarks/02-memory-bandwidth/}) extends the evaluation beyond \acs{CPU}-bound computation to test memory-allocation patterns and \acs{WASI}~P2 filesystem access behaviour. The worker-thread scaling experiment (Section~\ref{sec:eval_performance}) will quantify how effectively each variant exploits available \acs{CPU} parallelism when resource constraints are relaxed.

\textit{This chapter will be expanded with quantitative conclusions once the SpinKube benchmark measurements are complete.}
